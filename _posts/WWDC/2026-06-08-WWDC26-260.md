## 한 줄 요약

Device Hub 는 Xcode 27 과 함께 오는 별도 앱으로, 실기기와 simulator 를 같은 도구로 조작하고 정리하고 설정하게 해 주며, 실기기에서 찾은 bug 를 simulator 에서 재현하는 흐름을 한 곳에서 끝내게 한다.

---

## Device Hub 개요

앱이 모든 기기, 모든 appearance, 모든 text size 에서 제대로 보이게 하려면 확인할 조합이 많다. 세션은 이 일을 쉽게 해 주는 앱으로 Device Hub 를 소개하고, 기능을 훑은 뒤 실제 workflow 하나를 보여 준다.

---

### Device Hub 란?

Device Hub 는 Xcode 27 과 함께 제공되는 앱이고, 실기기와 simulator 를 다루는 작업의 중심이 되는 곳이다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-260/wwdc26-260-icon.png)
출처: WWDC26 - Get the most out of Device Hub

특징은 두 가지다.

- Xcode 를 실행하지 않아도 쓸 수 있다. 앱을 개발하는 사람만이 아니라 여러 기기 구성에서 test 하는 사람, 기기 재고를 관리하는 사람도 대상이다.
- 실기기든 simulator 든 같은 도구 묶음을 준다. 어느 쪽이든 필요한 대로 설정할 수 있다.

Device Hub 의 문서는 [Device Hub](https://developer.apple.com/documentation/xcode/device-hub){:target="_blank"} 에 있다.

---

### compact mode

앱을 개발하고 있다면 Device Hub 는 곧바로 만나게 된다. Xcode 에서 simulator 로 build and run 을 하면 자동으로 실행되고, 화면을 실시간으로 보여 주며 조작도 되는 window 가 뜬다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-260/wwdc26-260-compact-controls.png)

## Control

개발하다 보면 기기가 여기저기 흩어져 있다. 내 화면에서 기기를 조작할 수 있으면 하던 일에 집중하기 쉽다. 이 기능들은 window 가운데의 canvas 에 있다.

---

### canvas 의 화면 조작

canvas 에는 기기 화면이 실시간으로 나온다. 클릭, drag, scroll, trackpad gesture 로 직접 조작한다. 실기기와 simulator 가 똑같이 동작한다. 데모에서는 연결된 Apple Watch 를 Device Hub 에서 조작한다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-260/wwdc26-260-watch.png)
출처: WWDC26 - Get the most out of Device Hub

아래쪽에는 compact window 와 같은 device control 이 있고, 마찬가지로 기기에 따라 바뀐다.

---

### canvas 위쪽의 control

canvas 위에는 compact window 에 없는 control 이 있다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-260/wwdc26-260-canvas-controls.png)
출처: WWDC26 - Get the most out of Device Hub

| control | 하는 일 |
| --- | --- |
| Zoom | 확대와 축소. 실제 크기와 1:1 로 맞춰 앱을 실물 치수로 볼 수도 있다 |
| Resize mode | 앱의 크기를 자유롭게 바꾼다 |
| Capture keyboard | Mac 의 keystroke 를 기기로 바로 보낸다. key command 와 hardware keyboard 지원을 test 하기 쉽다 |
| compact 전환 | compact mode 로 돌아간다 |

Resize mode 는 [Modernize your UIKit app](https://developer.apple.com/videos/play/wwdc2026/278/){:target="_blank"} 세션에서 다룬다고 한다.

## Configure

기기를 정리해도 text size 를 바꿔 보고, 위치를 simulate 하고, profile 을 설치하는 일은 여전히 시간이 든다. Device Hub 는 오른쪽 inspector 에 panel 다섯 개를 둔다. tab 은 셋이고 셋째 tab 안에 panel 이 셋 있다.

---

### device settings

첫째 tab 은 기기가 보이는 모습과 동작을 바꾸는 곳이다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-260/wwdc26-260-settings.png)
출처: WWDC26 - Get the most out of Device Hub

| section | 내용 |
| --- | --- |
| appearance | dark mode, text size 등. 화면에는 Liquid Glass, Color Filter, Reduce Motion, Increase Contrast 도 보인다 |
| condition | 위치 변경처럼 앱이 조건 변화에 어떻게 반응하는지 test 한다 |
| audio | 소리 크기와 입출력 |

변경은 즉시 반영된다. 기기의 설정 앱을 뒤질 필요가 없다.

## devicectl

script 와 자동화에는 devicectl 을 쓴다.

---

### devicectl 이란?

devicectl 은 Device Hub 와 같은 기반 기술 위에 만든 command line tool 이다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-260/wwdc26-260-devicectl.png)
출처: WWDC26 - Get the most out of Device Hub

test 환경의 기기 관리, 여러 구성의 test, 앱 관리, 진단 자료 수집에 쓴다. 영상에 나온 명령은 다음과 같다.

```bash
# 기기 목록
devicectl list devices

# 기기에 앱 설치
devicectl device install app workouts.ipa --device "My iPhone"

# dark mode 로 전환
devicectl device settings appearance --mode dark --device "My iPhone"

# 기기 정보
devicectl device info details --device "My iPhone"

# 결과를 JSON file 로 저장
devicectl device info details --device "My iPhone" --json-output out.json
```

주석은 내가 붙였고 명령은 화면에 나온 그대로다. 구조화된 출력이 필요하면 `--json-output` option 을 써서 script 나 CI workflow 에 연결한다.

Xcode 27 에 든 devicectl(version 642.16)의 help 로 대조한 결과는 다음과 같다.

- `list devices`, `device install app`, `device settings appearance`, `device info details` 는 모두 있는 하위 명령이다. `--device` 는 이름, UDID, ECID, serial number 등을 받는다.
- `--mode` 가 받는 값은 light 와 dark 다.
- help 는 `--json-output` 으로 쓴 JSON 은 version 이 붙고 release 사이에 안정적으로 유지되며, 표준 출력은 사람이 읽는 용도라 안정성을 보장하지 않는다고 적는다. script 에서는 표준 출력을 parsing 하지 말고 JSON 을 써야 한다는 뜻이다.
- help 는 `device install app` 이 `.app` 확장자의 app bundle 을 설치한다고 설명하는데, 영상은 `workouts.ipa` 를 넘긴다.
- `device settings` 아래에는 appearance 말고도 audio, biometrics, reset, voiceover 가 있고, `device` 아래에는 capture, copy, orientation, pairings, pasteboard, profile, reboot, sysdiagnose, simulate 등이 있다. 세션이 보여 준 Device Hub 기능 대부분에 대응하는 명령이 있는 셈이다. 이 대응은 help 목록을 보고 내가 내린 해석이다.

내 Mac 에서는 `xcrun devicectl list devices` 로 실행했고, simulator 목록이 Name, Identifier, State, Model 열과 함께 나왔다. 실기기와 simulator 를 구분하는 열도 있었다.

## 정리

| 영역 | 위치 | 핵심 |
| --- | --- | --- |
| compact mode | Xcode 에서 run 하면 뜨는 window | 화면과 기기별 device control |
| Control | full window 의 canvas | 직접 조작, zoom, 실제 크기, resize mode, capture keyboard |
| Organize | sidebar | 전체 inventory, filter 와 정렬, quick action, tab 과 여러 compact window |
| Configure | inspector | device settings, diagnostic reports, Info, Apps, Profiles |
| 자동화 | devicectl | 같은 기능을 script 와 CI 에서 쓰고 JSON 으로 받는다 |

실제 프로젝트에 가져갈 점은 다음과 같다.

- layout 을 확인할 때는 크기가 다른 simulator 여러 개를 선택해 compact window 로 나란히 띄운다.
- text size, dark mode, 위치는 기기의 설정 앱 대신 inspector 에서 바꾼다. 즉시 반영된다.
- bug 를 넘길 때는 screenshot 만 보내지 말고 app data container 와 sysdiagnose 를 함께 보낸다. 받는 쪽은 container 를 바꿔 넣어 같은 상태에서 시작한다.
- 재현이 안 되면 screenshot 에서 방향, 위치, text size 같은 설정 차이를 하나씩 찾아 맞춘다. 세션의 bug 는 세 조건이 모두 맞아야 나왔다.
- 위치나 Bluetooth 처럼 특정 subsystem 의 문제를 볼 때는 해당 logging profile 을 먼저 설치하고 재부팅한 뒤 재현한다.
- CI 에서는 devicectl 과 `--json-output` 을 쓴다.
