## 한 줄 요약

search 를 어디에 두느냐가 무엇을 검색하는지와 얼마나 손이 잘 닿는지를 정한다. 위치는 앱의 navigation 과 search 의 scope 두 가지를 보고 고르고, 그 위에 suggestion, filter, 결과 없음 화면을 얹어서 search 를 완성한다.

---

## 세션의 구성

search 는 사람들이 찾고, 이동하고, 발견하게 돕는 핵심 도구다. 앱을 열고 가장 먼저 찾는 것일 때도 많다. Pages 에서 문서를 찾을 때, Apple TV 에서 영화를 고를 때, Apple Music 에서 다음에 들을 것을 찾을 때가 그렇다.

Liquid Glass 와 함께 search 에도 새 pattern 이 생겼다. iOS 에서는 손이 더 잘 닿는 자리로 옮겨 갔고, iPad 와 Mac 에서는 큰 화면을 살리는 쪽으로 정리됐다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-292/wwdc26-292-agenda.png)
출처: WWDC26 - Design intuitive search experiences

세션은 세 부분이다.

- Search field: search field 를 이루는 요소
- Patterns and placement: platform 마다 search 를 어디에 두는지, 그 자리를 어떻게 고르는지
- Best practices: suggestion, 결과 좁히기, 결과가 없을 때

## search field 의 구성 요소

search field 는 몇 가지 요소로 이루어져 있고, 놓인 자리에 따라 모양이 정해진다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-292/wwdc26-292-field.png)
출처: WWDC26 - Design intuitive search experiences

입력하기 전에는 두 가지가 보인다.

- leading 쪽의 search icon
- 무엇을 검색할 수 있는지 알려 주는 placeholder text

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-292/wwdc26-292-field-active.png)
출처: WWDC26 - Design intuitive search experiences

입력을 시작하면 두 가지가 더 나타난다.

- clear button: 입력한 글자를 한 번에 지운다
- Cancel button: iOS 에서 field 에 focus 가 있을 때 나타난다. 검색을 끝내고 keyboard 를 닫는다

field 의 style 은 놓인 자리에 따라 system 이 맞춘다. toolbar 에 있으면 glass 로 그려지고, scroll 되는 content 영역에 있으면 표준 content style 로 그려진다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-292/wwdc26-292-field-styles.png)
출처: WWDC26 - Design intuitive search experiences

자체 brand 의 icon 을 쓰는 앱이라도 이 요소들은 그대로 둔다. custom icon 을 쓴다면 그것이 대신하는 symbol 과 닮게 만든다. 돋보기는 어디서나 search 로 읽히는 기호이기 때문에, 모양이 멀어질수록 search 인지 알아보기 어려워진다.

## iOS 의 search 위치

iOS 에서 search 가 들어갈 수 있는 자리는 크게 셋이다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-292/wwdc26-292-ios-placements.png)
출처: WWDC26 - Design intuitive search experiences

- toolbar 의 field 또는 button
- tab bar 의 tab
- top toolbar 아래, 또는 content 영역 안의 field

어디에 두는지는 search 가 활성화됐을 때 field 가 어디로 가는지도 정한다. bottom toolbar 의 field 는 keyboard 바로 위로 올라온다. 손이 닿는 자리에 그대로 머문다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-292/wwdc26-292-bottom-keyboard.png)
출처: WWDC26 - Design intuitive search experiences

content 와 inline 으로 놓인 field 는 화면 위쪽에 남는다. 그 아래에 있는 UI 를 가리지 않기 위해서다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-292/wwdc26-292-inline-top.png)
출처: WWDC26 - Design intuitive search experiences

자리를 고를 때 세션은 두 가지를 묻는다.

- 사람들이 앱을 어떻게 navigate 하는가. tab bar 를 쓰는 앱인지, list 하나를 파고드는 앱인지에 따라 search 를 받아 줄 수 있는 자리가 달라진다.
- search 의 scope 가 무엇인가. search 가 놓인 자리는 그것이 무엇을 검색하는지에 대한 인식에 영향을 준다.

### Search Tab 이란?

Search Tab 은 tab bar 를 쓰는 앱에서 search 의 주 진입점이 되는 tab 이다. 세션은 tab 이 있는 앱이라면 이것을 search 의 주 진입점으로 삼으라고 권한다. 앱 안의 모든 관련 content 를 한 곳에서 찾을 수 있게 되기 때문이다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-292/wwdc26-292-tabbed.png)
출처: WWDC26 - Design intuitive search experiences

Search Tab 을 두는 방식은 둘이다.

첫째는 다른 tab 과 나란히 놓이는 표준 tab 이다. 선택하면 landing page 가 열리고 field 는 그 위쪽에 놓인다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-292/wwdc26-292-tab-standard.png)
출처: WWDC26 - Design intuitive search experiences

landing page 는 검색하기 전에 content 나 suggestion 을 보여 줄 자리가 된다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-292/wwdc26-292-tab-landing.png)
출처: WWDC26 - Design intuitive search experiences

둘째는 tab bar 에서 따로 떨어져 button 처럼 보이는 prominent tab 이다. tap 하면 landing page 를 거치지 않고 바로 search 와 keyboard 가 나타난다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-292/wwdc26-292-tab-prominent.png)
출처: WWDC26 - Design intuitive search experiences

어느 쪽을 고를지는 사람들이 그 앱에서 search 를 어떤 마음으로 쓰는지에 달려 있다.

Apple TV 는 표준 tab 을 쓴다. 무엇을 볼지 정하지 않고 들어오는 사람이 많기 때문에, landing page 에 genre 와 category 를 깔아서 둘러보는 흐름에 맞춘다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-292/wwdc26-292-apple-tv.png)
출처: WWDC26 - Design intuitive search experiences

Phone 앱은 prominent tab 을 쓴다. 최근 통화나 연락처를 빨리 찾는 것이 목적이라서, 어느 tab 에 있든 한 번의 tap 으로 입력을 시작할 수 있어야 한다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-292/wwdc26-292-phone.png)
출처: WWDC26 - Design intuitive search experiences

| 방식 | tap 했을 때 | 맞는 앱 |
| --- | --- | --- |
| 표준 tab | landing page 가 열리고 위쪽에 field | 둘러보다가 찾는 앱. 검색 전에 보여 줄 것이 있는 앱 |
| prominent tab | 바로 search 와 keyboard | 찾을 것이 정해져 있는 앱. 속도가 중요한 앱 |

### 특정 tab 안의 search

앱 전체가 아니라 한 tab 의 content 만 검색하는 경우도 있다. Apple Music 의 library 가 그렇다. field 는 제목 아래에 content 와 inline 으로 놓인다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-292/wwdc26-292-music-albums.png)
출처: WWDC26 - Design intuitive search experiences

여기서 scope 를 알려 주는 것은 둘이다.

- 화면의 제목
- 더 구체적으로 쓴 placeholder. Search 가 아니라 Search Albums 처럼 쓴다

이 자리는 앱에 search field 가 둘 이상 있거나, 자리 자체가 scope 를 알리는 데 중요할 때 쓸모가 있다. Search Tab 이 앱 전체를 맡고, inline field 가 지금 보는 list 를 맡는 식이다.

## search suggestion

자리를 정한 다음에는 search 자체를 다듬는다. 세션이 Best practices 로 묶은 것은 search suggestion, 결과 좁히기, 결과가 없을 때 셋이다.

### 최근 검색

recent searches 는 아무것도 입력하지 않고도 전에 찾던 것으로 돌아가게 해 준다. 보여 주는 자리는 platform 과 search 의 위치에 따라 다르다.

iOS 에서는 field 에 focus 가 가면 inline 으로 나타난다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-292/wwdc26-292-recents-ios.png)

- 지울 수 있게 한다. 항목 하나는 swipe 로 지우고, 전체는 section header 의 clear button 으로 지운다.

---

### 입력 중의 suggestion

입력을 시작하면 관련된 결과를 최대한 빨리 보여 주는 것이 먼저다. 그 위에 predictive suggestion 을 얹는다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-292/wwdc26-292-predictive.png)
출처: WWDC26 - Design intuitive search experiences

predictive suggestion 에는 세 가지 조건이 붙는다.

- 입력한 글자와 바로 이어져야 한다. 입력을 자연스럽게 완성한 것처럼 읽혀야 한다.
- 사용자가 입력한 부분과 system 이 예측한 부분을 시각적으로 구분한다. 영상에서는 입력한 부분이 진하게, 예측한 부분이 옅게 보인다.
- 개수를 제한한다. suggestion 이 화면을 채우면 결과가 밀려난다. 중심은 결과여야 한다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-292/wwdc26-292-user-input.png)
출처: WWDC26 - Design intuitive search experiences

결과의 순위가 좋으면 사람들은 끝까지 입력할 필요가 없다. suggestion 은 그 순위를 돕는 장치이지 대신하는 장치가 아니다.

---

## 결과 좁히기

여러 위치, category, account 를 한꺼번에 검색하는 앱에서는 결과를 좁히는 방법이 중요해진다. 원칙은 주 search field 를 넓게 시작하게 하고, 그다음에 좁힐 수 있게 하는 것이다. 처음부터 좁은 범위를 고르게 만들지 않는다.

---

### scope bar 란?

scope bar 는 search field 아래에 놓여서 검색 범위를 몇 개의 선택지로 바꾸게 해 주는 control 이다. 가벼운 filter 에 맞는다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-292/wwdc26-292-scope-bar.png)
출처: WWDC26 - Design intuitive search experiences

Mail 은 All Mailboxes 와 Current Mailbox 둘을 둔다. 결과를 좁히는 동시에, 지금 어디를 검색하고 있는지를 다시 알려 주는 역할도 한다.

SwiftUI 에서 이 자리에 해당하는 것은 [searchScopes(_:scopes:)](https://developer.apple.com/documentation/swiftui/view/searchscopes%28_:scopes:%29){:target="_blank"} 다. 세션은 API 를 말하지 않았고 이 대응은 내가 문서에서 찾아 붙인 것이다.

---

### 맥락에 맞는 filter

category 가 여럿인 앱은 더 다양한 filter 를 둘 수 있다. 조건은 지금 검색과 관련이 있고 맥락에 맞는 것만 보여 주는 것이다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-292/wwdc26-292-maps-filters.png)
출처: WWDC26 - Design intuitive search experiences

Maps 에서 Hiking 을 검색하면 All Lengths 와 All Route Types 같은 filter 가 나타난다. 식당을 검색할 때는 필요 없는 것들이다. filter 의 목록이 검색어를 따라 바뀐다.

---

### search token 이란?

search token 은 field 안에 들어가서 filter 로 동작하는 조각이다. 입력하는 도중에 keyword 로 제안되고, 고르면 field 안에서 강조된 text 로 바뀐다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-292/wwdc26-292-tokens.png)
출처: WWDC26 - Design intuitive search experiences

token 이 될 수 있는 것은 사람, 장소, content 의 종류 같은 것이다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-292/wwdc26-292-token-types.png)
출처: WWDC26 - Design intuitive search experiences

token 은 계속 더할 수 있고, 자연어처럼 조합된다. Photos 에서 Joshua Tree 와 2021 을 함께 넣으면 그 장소에서 그 해에 찍은 사진으로 좁혀진다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-292/wwdc26-292-photos-tokens.png)
출처: WWDC26 - Design intuitive search experiences

주의할 점이 하나 있다. token 은 입력해야 나타나기 때문에 눈에 덜 띈다. 그래서 보이는 filter UI 를 대신하게 두지 않는다. scope bar 같은 control 과 함께 쓴다.

| 방법 | 맞는 경우 | 주의할 점 |
| --- | --- | --- |
| scope bar | 선택지가 적은 가벼운 filter | 어디를 검색하는지도 함께 알린다 |
| 맥락에 맞는 filter | category 가 여럿인 앱 | 지금 검색과 관련 있는 것만 보여 준다 |
| search token | 사람, 장소, 종류를 조합해 좁힐 때 | 눈에 덜 띄므로 보이는 filter 와 함께 쓴다 |

---

## 결과가 없을 때

결과가 없을 때 빈 화면만 보여 주면 사람들은 검색이 실행되기는 했는지부터 의심한다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-292/wwdc26-292-no-results.png)
출처: WWDC26 - Design intuitive search experiences

이럴 때 쓰는 것이 content unavailable view 다. search 용으로 구성하면 세 가지를 보여 준다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-292/wwdc26-292-no-results-parts.png)
출처: WWDC26 - Design intuitive search experiences

- search symbol
- title: 결과가 없다는 것과 지금의 검색어
- subtitle: title 을 보충하는 한 줄. 영상의 화면에서는 철자를 확인하거나 다른 검색어를 써 보라는 안내로 보인다

핵심은 현재 검색어를 title 에 보여 주는 것이다. 영상의 화면은 Dsign 을 검색한 경우인데, 검색어가 그대로 보이기 때문에 오타라는 것을 바로 알아챌 수 있다.

SwiftUI 에서는 [ContentUnavailableView](https://developer.apple.com/documentation/swiftui/contentunavailableview){:target="_blank"} 의 search 용 구성이 이 모양에 해당한다. 이것도 세션에 나온 이름이 아니라 내가 문서에서 대응시킨 것이다.

## 정리

| 앱의 모양 | search 를 둘 자리 |
| --- | --- |
| iOS, list 를 따라 들어가는 앱 | bottom toolbar. 아래를 쓸 수 없으면 top toolbar |
| iOS, tab bar 가 있는 앱 | Search Tab. 둘러보는 앱은 표준 tab, 빨리 찾는 앱은 prominent tab |
| iOS, 한 tab 의 content 만 검색 | 제목 아래 inline field 와 구체적인 placeholder |
| iPad 와 Mac, split view | toolbar 의 trailing 쪽 |
| iPad 와 Mac, sidebar 의 목록을 검색 | sidebar 의 맨 위 |
| iPad 와 Mac, section 이 여럿 | 전용 tab 이나 sidebar item |

실제 프로젝트에 가져갈 점은 다음과 같다.

- search 의 자리를 정하기 전에 두 질문에 먼저 답한다. 앱을 어떻게 navigate 하는가, search 가 무엇을 검색하는가.
- iOS 에서 search 가 화면 위에 있다면 아래로 내릴 수 있는지 본다. 아래를 sheet 나 다른 UI 가 쓰고 있을 때만 위에 둔다.
- placeholder 를 Search 로만 두지 않는다. 범위가 좁은 field 는 Search Albums 처럼 대상을 적는다.
- custom search icon 을 쓰고 있다면 돋보기와 얼마나 닮았는지 다시 본다.
- recent searches 는 지울 수 있게 하고, 실제로 열어 본 결과만 남기는 방식을 검토한다.
- predictive suggestion 은 입력한 부분과 예측한 부분을 다르게 그리고, 개수를 줄인다.
- token 만으로 filter 를 제공하지 않는다. 보이는 filter 를 함께 둔다.
- 결과 없음 화면에 현재 검색어를 넣는다.
