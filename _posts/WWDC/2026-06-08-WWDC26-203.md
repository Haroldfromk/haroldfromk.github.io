## 한 줄 요약

iOS 27 의 PencilKit 은 `PKStrokeRecognizer` 로 손글씨를 text 로 읽고, 검색용 문자열을 만들고, drawing 안에서 단어의 위치를 찾는다. 인식은 전부 기기 안에서 일어난다. 여기에 `PKStrokePath` 와 Bézier path 사이의 변환, stroke 의 안정적인 identity 와 selection 제어, code 로 stroke 를 자르는 erasing 과 substroke 추출이 더해졌다. 합쳐 보면 `PKCanvasView` 를 쓰지 않는 앱도 손글씨 인식을 쓸 수 있고, stroke 하나하나를 추적하고 잘라서 animation 같은 기능을 만들 수 있게 되었다는 내용이다.

## PencilKit 과 올해의 주제

[PencilKit](https://developer.apple.com/documentation/pencilkit){:target="_blank"} 은 Apple platform 에서 손으로 그리는 입력을 담당하는 framework 다. 지연이 적은 canvas, 여러 가지 ink, Apple Pencil 지원, 그리고 그 아래의 data model 에 대한 접근을 제공한다. iOS 26 에서 나온 PaperKit 은 PencilKit 위에 만들어졌고, 세션에 따르면 이번에 소개하는 PencilKit 의 새 API 는 PaperKit 과 함께 쓸 때도 모두 쓸 수 있다.

Apple platform 의 손글씨 인식은 Freeform 과 Notes 의 손글씨 검색에서 이미 쓰이고 있었다. 세션은 PencilKit 에 가장 많이 들어온 요청 가운데 하나가 이 인식 기능이었다고 말한다. 이제 iOS, iPadOS, macOS, visionOS 27 에서 쓸 수 있다.

세션이 다루는 주제는 네 가지다.

1. Handwriting recognition: 손글씨를 인식된 단어로 바꾼다.
2. Path conversion: PencilKit 의 stroke path 와 표준 Bézier path 를 서로 변환한다.
3. Improved model access: stroke identity 와 selection 접근.
4. Stroke slicing: stroke 를 나누거나 일부 구간을 뽑아낸다.

## Handwriting recognition

handwriting recognition 의 중심은 `PKStrokeRecognizer` 다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-203/wwdc26-203-recognizer.png)
출처: WWDC26 - Read between the strokes with PencilKit

`PKStrokeRecognizer` 는 Swift actor 다. 그래서 설계부터 thread-safe 하다. 인식에는 시간이 걸리므로 method 는 모두 asynchronous 다. 쓰는 순서는 세 가지 기능 모두 같다. recognizer 를 만들고, `updateDrawing(_:)` 으로 인식할 `PKDrawing` 을 넘기고, 결과를 묻는다.

#### PKStrokeRecognizer

[PKStrokeRecognizer](https://developer.apple.com/documentation/pencilkit/pkstrokerecognizer){:target="_blank"} 는 `PKDrawing` 의 stroke 를 text 로 인식하는 actor 다. iOS 27, macOS 27, visionOS 27 부터 쓸 수 있다.

#### updateDrawing(_:)

[updateDrawing(_:)](https://developer.apple.com/documentation/pencilkit/pkstrokerecognizer/updatedrawing%28_:%29){:target="_blank"} 는 recognizer 가 인식할 drawing 을 바꾸는 async method 다. 지금 들고 있는 drawing 은 [drawing](https://developer.apple.com/documentation/pencilkit/pkstrokerecognizer/drawing){:target="_blank"} property 로 읽는다.

세션은 이 recognizer 의 능력을 세 가지로 나눈다. Recognized text, Indexable content, Find text 다.

### Recognized text

첫 번째는 쓴 내용에 대해 가장 그럴듯한 결과 하나를 돌려주는 기능이다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-203/wwdc26-203-recognized-text.png)
출처: WWDC26 - Read between the strokes with PencilKit

slide 의 요점은 세 가지다.

- 가장 가능성이 높은 결과 하나를 돌려준다.
- 기본으로는 기기의 언어 설정으로 손글씨를 해석한다. `preferredLanguages` 를 직접 지정해서 앱의 언어 맥락에 맞출 수도 있다.
- drawing 전체를 한 번에 인식할 수도 있고, 일부 stroke 의 ID 만 넘길 수도 있다.

```swift
import PencilKit
import UIKit

@MainActor
func showRecognizedText(drawing: PKDrawing, myLabel: UILabel) async {
    let recognizer = PKStrokeRecognizer()
    await recognizer.updateDrawing(drawing)
    myLabel.text = await recognizer.recognizedText()
}
```

세션 snippet 의 세 줄을 그대로 두고 함수로 감쌌다. `UILabel` 에 값을 넣으므로 `@MainActor` 를 붙였다.

#### recognizedText(strokeIDs:)

[recognizedText(strokeIDs:)](https://developer.apple.com/documentation/pencilkit/pkstrokerecognizer/recognizedtext%28strokeids:%29){:target="_blank"} 는 인식 결과를 `String?` 으로 돌려주는 async method 다. `strokeIDs` 의 기본값은 `nil` 이고, 이때는 drawing 전체를 인식한다. `Set<UUID>` 를 넘기면 그 stroke 들만 인식한다.

언어를 지정하고 일부 stroke 만 인식하는 경우는 세션에 code 가 없다. SDK 의 선언대로 쓰면 다음과 같다.

```swift
func recognizeChinese(drawing: PKDrawing, strokeIDs: Set<UUID>) async -> String? {
    let recognizer = PKStrokeRecognizer(
        preferredLanguages: [Locale.Language(identifier: "zh-Hans")]
    )
    await recognizer.updateDrawing(drawing)
    return await recognizer.recognizedText(strokeIDs: strokeIDs)
}
```

#### init(preferredLanguages:)

[init(preferredLanguages:)](https://developer.apple.com/documentation/pencilkit/pkstrokerecognizer/init%28preferredlanguages:%29){:target="_blank"} 는 인식에 쓸 언어를 `[Locale.Language]?` 로 받는 initializer 다. `nil` 이면 기기의 언어를 따른다. 실제로 쓰이는 언어는 [languages](https://developer.apple.com/documentation/pencilkit/pkstrokerecognizer/languages){:target="_blank"} property 로 확인한다.

demo 에서는 flashcard 옆의 자유 연습 화면으로 넘어가서 아무 글이나 쓴다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-203/wwdc26-203-hello.png)
출처: WWDC26 - Read between the strokes with PencilKit

이 화면에는 Clear, Recognize, Replay 버튼이 있고 아래가 전부 canvas 다. 발표자가 "Hello WWDC" 를 쓰고, 앱이 그것을 그대로 인식한다.

iOS 27 기준으로 `PKStrokeRecognizer` 는 29개 언어를 지원한다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-203/wwdc26-203-languages.png)
출처: WWDC26 - Read between the strokes with PencilKit

지원 언어 목록은 `supportedLanguages` 로 얻는다. 주의할 점이 하나 있다. Simulator 에서의 손글씨 인식은 Latin 문자를 쓰는 언어만 지원한다. 한국어나 중국어 인식은 실제 기기에서 확인해야 한다는 뜻이다.

macOS 27.0.1 에서 이 집합을 찍어 보면 33개가 나온다. 광둥어가 간체와 번체로, 힌디어가 Devanagari 와 Latin 으로, 노르웨이어가 `no`, `nb`, `nn` 으로 따로 들어 있어서 slide 의 29 와 수가 맞지 않는다. 한국어 (`ko`) 와 일본어 (`ja`) 도 들어 있다. 언어 수를 code 에 고정하지 말고 아래처럼 `contains` 로 묻는다.

```swift
func canRecognize(_ language: Locale.Language) -> Bool {
    PKStrokeRecognizer.supportedLanguages.contains(language)
}
```

#### supportedLanguages

[supportedLanguages](https://developer.apple.com/documentation/pencilkit/pkstrokerecognizer/supportedlanguages){:target="_blank"} 는 인식할 수 있는 언어의 집합이다. type 은 `Set<Locale.Language>` 이고 static property 라서 instance 를 만들지 않고 읽는다.

인식이 어디서 일어나는지도 세션이 따로 짚는다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-203/wwdc26-203-on-device.png)
출처: WWDC26 - Read between the strokes with PencilKit

- 인식은 전부 기기 안에서 실행된다.
- 인식 model 은 offline 으로 동작하고 운영체제에 포함되어 있다.
- 빠르고, iOS 27 을 지원하는 모든 기기에서 동작한다.

### Indexable content

두 번째는 drawing 전체의 내용을 나타내는 문자열 하나를 돌려주는 기능이다. Spotlight 검색 같은 기능에 쓴다.

Recognized text 와 다른 점은 모호한 글씨를 다루는 방식이다. 여러 언어가 활성화되어 있으면 Indexable content 에는 그 언어들 가운데 둘 이상의 결과가 들어갈 수 있다. 그리고 글씨가 모호할 때는 가능한 해석을 전부 index 에 넣어야 사용자가 무엇으로 검색하든 자기 글을 찾을 수 있다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-203/wwdc26-203-ambiguous.png)
출처: WWDC26 - Read between the strokes with PencilKit

세션이 드는 예가 이 글씨다. 숫자 "1" 인지 소문자 "l" 인지, "101" 인지 "lol" 인지 알 수 없다. Recognized text 는 가장 좋은 답 하나를 주고, Indexable content 는 모든 후보를 이어 붙여서 준다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-203/wwdc26-203-indexable.png)
출처: WWDC26 - Read between the strokes with PencilKit

Indexable content 를 disk 에 저장할 때 기억할 것이 두 가지 있다.

첫째, 인식 결과는 model 이 update 되면서 시간이 지나면 좋아질 수 있다. 그래서 recognizer 의 version 을 index 와 함께 저장해 두고, 다시 읽을 때 현재 version 과 비교해서 re-index 할지를 정한다.

둘째, `PKStrokeRecognizer` 호출을 throttle 한다. stroke 하나마다 결과를 갱신하면 indexing 기능에 필요한 것보다 전력을 더 쓴다.

```swift
struct HandwritingIndex: Codable {
    let text: String
    let version: Int
}

func makeIndex(drawing: PKDrawing) async -> HandwritingIndex? {
    let recognizer = PKStrokeRecognizer()
    await recognizer.updateDrawing(drawing)
    guard let indexedContent = await recognizer.indexableContent else { return nil }
    return HandwritingIndex(
        text: indexedContent,
        version: PKStrokeRecognizer.recognitionVersion
    )
}

func needsReindex(_ saved: HandwritingIndex) -> Bool {
    saved.version != PKStrokeRecognizer.recognitionVersion
}
```

세션 snippet 은 `indexableContent` 를 꺼내서 `index(text:)` 에 넘기는 데까지다. version 을 같이 저장하고 비교하는 부분은 세션이 말로 설명한 것을 내가 code 로 옮겼다.

세션과 SDK 가 다른 곳이 하나 있다. 발표와 slide 는 이 property 를 `recognizerVersion` 이라고 부르지만, Xcode 27.0 의 SDK 에 있는 이름은 `recognitionVersion` 이고 static property 다. `recognizer.recognizerVersion` 으로 쓰면 compile 되지 않는다.

#### indexableContent

[indexableContent](https://developer.apple.com/documentation/pencilkit/pkstrokerecognizer/indexablecontent){:target="_blank"} 는 drawing 전체에 대한 검색용 문자열을 `String?` 으로 돌려주는 async property 다. 모호한 글씨의 후보가 모두 들어 있으므로 화면에 보여 주는 용도가 아니라 index 에 넣는 용도다.

#### recognitionVersion

[recognitionVersion](https://developer.apple.com/documentation/pencilkit/pkstrokerecognizer/recognitionversion){:target="_blank"} 은 인식 model 의 version 을 나타내는 `Int` 다. 저장해 둔 값과 다르면 예전에 만든 index 가 지금의 인식 결과와 다를 수 있다.

### Find text

세 번째는 text 검색이다. 찾을 문자열을 주면 그 단어가 drawing 의 어디에 있을 법한지를 검색 결과의 배열로 돌려준다. 이때도 모든 후보를 고려한다. 일치하는 stroke 주위에 highlight 가 뜨는 대화형 검색이 이 기능으로 만들어진다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-203/wwdc26-203-find-text.png)
출처: WWDC26 - Read between the strokes with PencilKit

```swift
func matchBounds(of query: String, in drawing: PKDrawing) async -> [CGRect] {
    let recognizer = PKStrokeRecognizer()
    await recognizer.updateDrawing(drawing)
    let results = await recognizer.search(query)
    return results.map(\.bounds)
}
```

세션 snippet 은 `search("apple")` 의 결과를 돌면서 `highlight(bounds:)` 를 부른다. `highlight` 는 세션에 정의가 없는 함수라서, 여기서는 bounds 의 배열을 돌려주는 함수로 바꿨다.

#### search(_:fullWordsOnly:caseMatchingOnly:)

[search(_:fullWordsOnly:caseMatchingOnly:)](https://developer.apple.com/documentation/pencilkit/pkstrokerecognizer/search%28_:fullwordsonly:casematchingonly:%29){:target="_blank"} 는 drawing 에서 문자열을 찾아 `[SearchResult]` 를 돌려주는 async method 다. `fullWordsOnly` 와 `caseMatchingOnly` 는 둘 다 기본값이 `false` 다. 세션은 이 두 parameter 를 따로 설명하지 않는다.

#### SearchResult

[PKStrokeRecognizer.SearchResult](https://developer.apple.com/documentation/pencilkit/pkstrokerecognizer/searchresult){:target="_blank"} 는 검색 결과 하나를 나타내는 struct 다. 일치한 stroke 의 ID 인 `strokes` (`Set<UUID>`) 와 그 영역인 `bounds` (`CGRect`) 를 가진다.

`search()` 는 system 의 찾기와 바꾸기 UI 인 [UIFindInteraction](https://developer.apple.com/documentation/uikit/uifindinteraction){:target="_blank"} 과도 잘 맞는다. `UIFindInteractionDelegate` 를 구현하고 그 안에서 `search()` 를 쓰면, 결과 사이를 이동하고 highlight 하는 system 검색 UI 를 drawing canvas 에서 그대로 쓸 수 있다. 세션은 이 연결을 말로만 설명하고 code 는 보여 주지 않는다.

flashcard 앱도 정답 확인에 이 search 를 쓴다. 발표자는 `SearchResult` 가 돌려준 bounds 를 눈으로 볼 수 있게 앱을 고쳐서 보여 준다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-203/wwdc26-203-search-bounds.png)
출처: WWDC26 - Read between the strokes with PencilKit

카드의 단어는 "Cloud" 이고 쓴 글자는 "云" 이다. search 가 일치한 곳에 상자가 그려진다.

## Path conversion

path conversion 은 PencilKit 을 내 앱에 들여오는 데 쓰는 API 묶음이다. 먼저 PencilKit 이 stroke 의 path 를 어떻게 저장하는지를 알아야 한다.

---

### B-spline 이란?

B-spline 은 control point 의 나열로 곡선을 정의하는 방식이다. Bézier 곡선과 달리 곡선이 control point 를 직접 지나지 않고, 이웃한 control point 몇 개가 함께 곡선의 한 구간을 정한다. cubic 은 구간마다 control point 네 개가 관여한다는 뜻이고, uniform 은 control point 사이의 parameter 간격이 일정하다는 뜻이다. 구간과 구간이 부드럽게 이어지는 것이 구조에서 보장되므로 손으로 그린 선을 표현하기에 알맞다.

PencilKit 은 stroke path 를 cubic uniform B-spline 으로 표현한다. 저장 방식에 대한 자세한 설명은 WWDC20 의 [Inspect, modify, and construct PencilKit drawings](https://developer.apple.com/videos/play/wwdc2020/10148/){:target="_blank"} 에 있다고 세션이 안내한다.

---

### Bézier path 와의 변환

B-spline 은 drawing 에 좋은 표현이지만 Bézier path 만큼 흔하지는 않다. iOS 27 에서 `PKStrokePath` 는 둘 사이의 변환을 지원한다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-203/wwdc26-203-spline-conversion.png)
출처: WWDC26 - Read between the strokes with PencilKit

변환할 때 geometry 는 PencilKit 이 처리한다. 다만 Bézier path 에는 size, opacity, force 같은 PencilKit 의 property 가 없다. 그래서 Bézier path 에서 `PKStrokePath` 를 만들 때는 control point 마다 그 값을 개발자가 제공해야 한다.

반대 방향에 대해서 세션이 보장하는 것이 있다. `PKStrokePath` 에서 시작해서 Bézier path 로 바꿨다가 되돌리면 control point 의 위치가 같다. 그래서 PencilKit stroke 를 Bézier 기반 format 으로 저장해 두었다가 손실 없이 복원할 수 있다.

```swift
func strokePath(from bezierPath: CGPath) -> PKStrokePath {
    PKStrokePath(bezierPath: bezierPath, creationDate: Date()) { point in
        PKStrokePoint(
            location: point.location,
            timeOffset: 0,
            size: CGSize(width: 4, height: 4),
            opacity: 1,
            force: 1,
            azimuth: 0,
            altitude: .pi / 2
        )
    }
}

func bezierPaths(from drawing: PKDrawing) -> [CGPath] {
    drawing.strokes.map { $0.path.bezierRepresentation }
}
```

이 code 는 세션에 없다. SDK 의 선언을 보고 썼다. size 와 opacity 같은 값은 예로 넣은 고정값이다.

#### init(bezierPath:creationDate:pointProvider:)

[init(bezierPath:creationDate:pointProvider:)](https://developer.apple.com/documentation/pencilkit/pkstrokepath-swift.struct/init%28bezierpath:creationdate:pointprovider:%29){:target="_blank"} 는 `CGPath` 로 `PKStrokePath` 를 만드는 initializer 다. `pointProvider` closure 는 변환된 control point 마다 불리고, 그 자리에 놓을 `PKStrokePoint` 를 돌려줘야 한다.

#### ConvertedBezierPoint

[PKStrokePath.ConvertedBezierPoint](https://developer.apple.com/documentation/pencilkit/pkstrokepath-swift.struct/convertedbezierpoint){:target="_blank"} 는 `pointProvider` 가 받는 값이다. `location` 외에 `index`, `pointCount`, `bezierSegmentIndex` 를 가지고 있어서, path 의 어느 위치인지에 따라 굵기나 opacity 를 다르게 줄 수 있다.

#### bezierRepresentation

[bezierRepresentation](https://developer.apple.com/documentation/pencilkit/pkstrokepath-swift.struct/bezierrepresentation){:target="_blank"} 은 `PKStrokePath` 를 `CGPath` 로 바꾼 값이다.

### PKCanvasView 없는 손글씨 인식

이 변환이 handwriting recognition 과 만나는 곳이 있다. 앱이 자체 canvas 를 가지고 있고 stroke 를 Bézier path 로 저장하고 있다면, 그것을 `PKStrokePath` 로 바꾸고, `PKDrawing` 을 만들고, `PKStrokeRecognizer` 에 넣을 수 있다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-203/wwdc26-203-bezier-recognize.png)
출처: WWDC26 - Read between the strokes with PencilKit

그러면 손글씨 인식이 `PKCanvasView` 만이 아니라 어떤 canvas 와도 함께 쓸 수 있는 기능이 된다.

```swift
func drawing(from bezierPaths: [CGPath]) -> PKDrawing {
    let ink = PKInk(.pen, color: .black)
    let strokes = bezierPaths.map { PKStroke(ink: ink, path: strokePath(from: $0)) }
    return PKDrawing(strokes: strokes)
}
```

위에서 만든 `strokePath(from:)` 을 써서 Bézier path 의 배열을 `PKDrawing` 으로 만든다. 이 drawing 을 앞의 `showRecognizedText` 나 `matchBounds` 에 넘기면 된다. 이 code 도 세션에 없고 내가 쓴 것이다. 인식만 할 것이라면 ink 의 종류는 결과에 중요하지 않을 것으로 보이지만 확인하지는 않았다.

### stroke identity 와 selection

`PKStroke` 와 `PKStrokePath` 가 둘 다 `Identifiable` protocol 을 따르게 되었다. ID 는 안정적인 UUID 다. stroke 를 transform 하거나 편집하거나 undo 를 해도 같은 stroke 를 계속 추적할 수 있다. 앞에서 본 `recognizedText(strokeIDs:)` 와 `SearchResult.strokes` 가 쓰는 UUID 가 이 ID 다.

안정적인 identity 가 생겼으므로 `PKCanvasView` 의 selection 상태를 code 로 제어할 수 있다. 사용자의 selection 이 바뀔 때마다 불리는 delegate method 도 새로 생겼다.

```swift
final class SelectionObserver: NSObject, PKCanvasViewDelegate {
    func canvasViewSelectionDidChange(_ canvasView: PKCanvasView) {
        let selected: Set<UUID> = canvasView.selection
        print(selected.count)
    }
}

@MainActor
func selectLastStroke(in canvasView: PKCanvasView) {
    guard let last = canvasView.drawing.strokes.last else { return }
    canvasView.selection = [last.id]
}
```

이 code 는 세션에 없다. SDK 의 선언을 보고 썼다.

#### id

[PKStroke.id](https://developer.apple.com/documentation/pencilkit/pkstroke-swift.struct/id){:target="_blank"} 와 [PKStrokePath.id](https://developer.apple.com/documentation/pencilkit/pkstrokepath-swift.struct/id){:target="_blank"} 는 `Identifiable` 의 요구 사항인 `UUID` 다. SDK 에서 `PKStroke` 의 `id` 는 읽고 쓸 수 있고 `PKStrokePath` 의 `id` 는 읽기 전용이다.

#### selection

[selection](https://developer.apple.com/documentation/pencilkit/pkcanvasview/selection){:target="_blank"} 은 `PKCanvasView` 에서 선택된 stroke 의 ID 집합이다. type 은 `Set<UUID>` 이고 값을 넣으면 선택이 바뀐다. SDK 의 선언에는 iOS 27 과 visionOS 27 만 적혀 있다.

#### canvasViewSelectionDidChange(_:)

[canvasViewSelectionDidChange(_:)](https://developer.apple.com/documentation/pencilkit/pkcanvasviewdelegate/canvasviewselectiondidchange%28_:%29){:target="_blank"} 는 selection 이 바뀔 때 불리는 `PKCanvasViewDelegate` 의 method 다.

---

### wet ink 와 renderGroupID

어떤 ink 는 빠르게 이어서 그리면 ink 가 아직 마르지 않은 것처럼 stroke 들이 함께 합성된다. PencilKit 은 이 stroke 들에 같은 `renderGroupID` 를 주어서 이것을 구현한다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-203/wwdc26-203-wet-ink.png)
출처: WWDC26 - Read between the strokes with PencilKit

slide 는 같은 두 stroke 를 `renderGroupID` 가 다를 때와 같을 때로 나누어 보여 준다. 다르면 겹친 부분이 따로 칠한 것처럼 진해지고, 같으면 한 번에 칠한 것처럼 합쳐진다. iOS 27 에서는 이 값을 개발자가 제어할 수 있다.

[renderGroupID](https://developer.apple.com/documentation/pencilkit/pkstroke-swift.struct/rendergroupid){:target="_blank"} 는 `PKStroke` 의 `UUID?` property 다. 세션은 여기까지만 말한다. SDK 에는 이것과 함께 `PKStroke` 의 [renderState](https://developer.apple.com/documentation/pencilkit/pkstroke-swift.struct/renderstate-swift.property){:target="_blank"} 와 `id`, `renderGroupID`, `renderState` 를 모두 받는 새 initializer 도 들어 있다. 이 부분은 문서 [Controlling stroke rendering for animation and editing](https://developer.apple.com/documentation/pencilkit/controlling-stroke-rendering-for-animation-and-editing){:target="_blank"} 이 다룬다.

## Stroke slicing

마지막 API 묶음은 stroke 를 자르는 두 가지 방법이다. Programmatic erasing 과 Substroke extraction 이다.

---

### stroke mask 란?

stroke mask 는 stroke 에서 보이는 부분을 정하는 영역이다. PencilKit 은 stroke 의 일부를 지웠을 때 path 자체를 고치지 않고 mask 로 표현한다. pixel eraser 가 stroke 의 일부를 지우면, 남아서 보이는 부분이 mask 로 정의된다. PencilKit 의 data model 을 다뤄 본 사람에게는 익숙한 개념이다.

---

### Programmatic erasing

iOS 27 부터는 이 지우기를 code 로 할 수 있다. 지우개 역할을 할 `PKStrokePath` 를 넘긴다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-203/wwdc26-203-erasing-before.png)
출처: WWDC26 - Read between the strokes with PencilKit

지우개 path 가 drawing 을 가로지르면 stroke 하나가 각자의 mask 를 가진 여러 개의 독립된 stroke 로 나뉜다. 사용자가 canvas 에서 eraser tool 을 쓴 것과 같은 결과다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-203/wwdc26-203-erasing-after.png)
출처: WWDC26 - Read between the strokes with PencilKit

```swift
func erase(_ drawing: inout PKDrawing, along eraserPath: PKStrokePath) {
    drawing.erasePath(eraserPath)
}
```

이 code 는 세션에 없다. SDK 의 선언을 보고 썼다.

#### erasePath(_:mask:transform:)

`erasePath(_:mask:transform:)` 는 [PKDrawing](https://developer.apple.com/documentation/pencilkit/pkdrawing-swift.struct){:target="_blank"} 의 mutating method 다. 첫 argument 가 지우개가 되는 `PKStrokePath` 이고, `mask` 의 기본값은 `nil`, `transform` 의 기본값은 `.identity` 다. drawing 을 바꾸지 않고 지운 결과를 새 `PKDrawing` 으로 돌려주는 `erasingPath(_:mask:transform:)` 도 함께 있다.

세션은 성능에 대한 주의를 덧붙인다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-203/wwdc26-203-erasing-performance.png)
출처: WWDC26 - Read between the strokes with PencilKit

복잡한 drawing 에서는 slicing 의 비용이 클 수 있다. stroke 가 많은 drawing 이라면 UI 를 막지 말고 background thread 에서 지우는 것을 고려한다. `PKDrawing` 은 값 type 이라서 `erasingPath` 로 새 drawing 을 만든 다음 main 에서 canvas 에 넣는 구조로 쓸 수 있다.

---

### Substroke extraction

erasing 이 stroke 를 눈에 보이게 자르는 것이라면, substroke extraction 은 stroke 의 한 구간을 새 stroke 나 path 로 효율적으로 얻는 것이다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-203/wwdc26-203-substroke.png)
출처: WWDC26 - Read between the strokes with PencilKit

path 위의 어느 지점이든 parametric range 로 지정해서 구간을 꺼낸다. slice 가 어디서 시작하고 끝나는지를 정확하게 제어할 수 있다. PencilKit 의 ink 에는 pencil texture 의 particle 처럼 stroke 전체를 기준으로 위치가 정해지는 요소가 있는데, substroke 를 꺼낼 때 PencilKit 이 이 particle 의 일관성을 유지해 준다. 잘라 낸 조각의 질감이 원래 stroke 의 그 자리와 같다는 뜻이다.

```swift
func leadingPart(of stroke: PKStroke, upTo end: CGFloat) -> PKStroke {
    stroke.substroke(range: 0...end)
}

func leadingPart(of path: PKStrokePath, upTo end: CGFloat) -> PKStrokePath {
    path[0...end]
}
```

이 code 는 세션에 없다. SDK 의 선언을 보고 썼다.

세션과 SDK 가 다른 곳이 여기에도 있다. 세션은 `PKStroke` 와 `PKStrokePath` 가 둘 다 subscript 접근을 지원한다고 말한다. Xcode 27.0 의 SDK 에서는 subscript 가 `PKStrokePath` 에만 있고, `PKStroke` 쪽은 `substroke(range:)` 라는 method 다.

#### substroke(range:)

[substroke(range:)](https://developer.apple.com/documentation/pencilkit/pkstroke-swift.struct/substroke%28range:%29){:target="_blank"} 는 `ClosedRange<CGFloat>` 로 지정한 구간을 새 `PKStroke` 로 돌려주는 method 다.

#### subscript(_:)

[subscript(_:)](https://developer.apple.com/documentation/pencilkit/pkstrokepath-swift.struct/subscript%28_:%29){:target="_blank"} 는 `PKStrokePath` 에서 `ClosedRange<CGFloat>` 구간을 새 `PKStrokePath` 로 꺼낸다. range 의 값은 control point 의 index 를 실수로 확장한 parametric value 다.

demo 는 이 API 로 만든 기능을 보여 준다. 한자는 획을 쓰는 순서가 중요하다. 발표자는 순서가 맞는지 확인할 수 있도록, 자신이 글자를 쓴 과정을 substroke 로 다시 재생하는 기능을 만들었다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-203/wwdc26-203-replay-a.png)
출처: WWDC26 - Read between the strokes with PencilKit

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-203/wwdc26-203-replay-b.png)
출처: WWDC26 - Read between the strokes with PencilKit

"云" 이 쓴 순서대로 한 획씩 다시 그려진다. 세션은 PencilKit 의 rendering 이 Metal 로 구현되어 있고 최적화되어 있어서 이 animation 이 부드럽다고 설명한다. 재생을 어떻게 구현했는지는 세션에서 code 로 보여 주지 않고, sample code 에 들어 있다고만 안내한다.

## 세션의 마무리

세션이 권하는 다음 단계는 네 가지다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-06-08-WWDC26-203/wwdc26-203-next.png)
출처: WWDC26 - Read between the strokes with PencilKit

- `PKStrokeRecognizer` 를 도입해서 앱에 handwriting recognition 을 넣는다.
- 기존의 Bézier path 를 `PKStrokePath` 로 변환해서, `PKCanvasView` 없이도 handwriting recognition 을 쓴다.
- stable identity 로 stroke 를 추적하고 selection 변화에 반응해서 더 깊이 있는 custom 경험을 만든다.
- programmatic erasing 으로 drawing 을 자르고 substroke 로 부드러운 animation 을 만든다.

API 하나하나는 붙이기 쉽고, 합치면 전에는 만들 수 없던 기능이 가능해진다는 말로 세션이 끝난다.

---

## 정리

세션에 나온 API 를 주제별로 모으면 다음과 같다.

| 주제 | API | 하는 일 | 주의할 점 |
| --- | --- | --- | --- |
| Recognized text | `recognizedText(strokeIDs:)` | 가장 그럴듯한 결과 하나 | Simulator 는 Latin 문자 언어만 |
| Indexable content | `indexableContent`, `recognitionVersion` | 모든 후보를 이어 붙인 검색용 문자열 | version 을 같이 저장, 호출은 throttle |
| Find text | `search(_:fullWordsOnly:caseMatchingOnly:)` | 단어가 있을 법한 위치의 stroke 와 bounds | `UIFindInteraction` 과 연결 가능 |
| Path conversion | `init(bezierPath:creationDate:pointProvider:)`, `bezierRepresentation` | Bézier path 와 `PKStrokePath` 의 상호 변환 | size, opacity, force 는 직접 제공 |
| Model access | `id`, `selection`, `canvasViewSelectionDidChange(_:)`, `renderGroupID` | stroke 추적, selection 제어, wet ink 합성 제어 | `selection` 은 SDK 에 iOS 27 과 visionOS 27 만 표시 |
| Stroke slicing | `erasePath(_:mask:transform:)`, `substroke(range:)`, `PKStrokePath` 의 subscript | code 로 지우기, 구간 추출 | 복잡한 drawing 에서는 background 에서 |

실제 프로젝트에 가져갈 점은 다음과 같다.

- 인식 결과를 화면에 보여 줄 때는 `recognizedText`, 검색 index 에 넣을 때는 `indexableContent` 를 쓴다. 둘은 용도가 다르고 서로 대신할 수 없다.
- index 를 저장할 때는 `PKStrokeRecognizer.recognitionVersion` 을 같이 저장하고, 값이 달라졌으면 다시 만든다.
- stroke 가 추가될 때마다 인식을 돌리지 않는다. 입력이 잠시 멈췄을 때 한 번 돌리는 식으로 throttle 한다.
- 지원 언어는 고정된 목록으로 가정하지 말고 `supportedLanguages` 로 확인한다.
- 한국어를 포함해 Latin 문자가 아닌 언어의 인식은 Simulator 가 아니라 실제 기기에서 test 한다.
- 자체 canvas 를 가진 앱이라면 canvas 를 바꾸지 않고도 Bézier path 를 `PKDrawing` 으로 변환해서 인식만 붙일 수 있다.
- 세션의 이름과 SDK 의 이름이 다른 곳이 있다. `recognizerVersion` 이 아니라 `recognitionVersion` 이고, `PKStroke` 의 구간 추출은 subscript 가 아니라 `substroke(range:)` 다.
