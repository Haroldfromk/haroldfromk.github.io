며칠씩 걸리던 일 네 가지를 Claude Code로 몇 분 안에 끝내는 시연 강의다. 처음 보는 코드 파악, 음성으로 새 앱 만들기, 버그 수정, 코드 밖 업무(데이터 정리와 발표 자료)를 차례로 보여 준다. 개념 설명보다 무엇을 할 수 있는지 감을 잡게 하는 데 목적이 있다.

---

## 네 시연의 공통 흐름

네 시연 모두 같은 순서로 시작한다.

1. 작업할 폴더에서 터미널을 연다. 폴더를 우클릭해 "폴더에서 새 터미널 열기"를 누르거나 `cd <경로>`로 이동한다.
2. `claude`를 실행해 그 폴더에서 세션을 시작한다.
3. `Shift+Tab`을 몇 번 눌러 자동 모드(auto mode)로 바꾼다.
4. 프롬프트를 보내고 기다린다.

---

### 자동 모드란?

Claude Code는 파일을 고치거나 명령을 실행하기 전에 "해도 될까요?" 하고 묻는다. 자동 모드는 이 확인을 건너뛰고 끝까지 진행하는 권한 모드다. 시연처럼 결과를 빨리 보고 싶을 때 편하지만, 무엇이 바뀌는지 중간에 볼 기회가 줄어든다. 권한 모드의 종류는 S01-09 강의 내용이다.

---

## 처음 보는 프로젝트 파악하기

예제는 오픈 소스 화이트보드 앱 Excalidraw다. GitHub에서 zip으로 받아 압축을 푼 `excalidraw-master` 폴더에서 세션을 열었다.

첫 프롬프트는 새로 들어온 팀원에게 설명하듯 요청했다. 앱이 하는 일, 기술 스택(tech stack, 앱을 만드는 데 쓴 언어와 도구 묶음), 폴더 구조, 어디부터 읽으면 되는지를 묻고, 설명마다 근거가 된 파일을 붙여 달라고 했다. 40초 만에 React와 TypeScript로 된 앱이라는 것, 폴더별 용도, 주요 파일 내용이 정리되어 나왔다.

두 번째 프롬프트는 흐름 추적이었다. 사용자가 사각형을 그릴 때 마우스 클릭부터 화면에 도형이 나타나기까지 코드에서 무슨 일이 일어나는지 따라가 달라고 했다. 그 흐름을 Mermaid 다이어그램으로 그리고 앞의 개요까지 합쳐 `onboarding.md`로 저장해 달라고 했다. 2분 7초 뒤 프로젝트 폴더에 `onboarding.md`가 생겼고, 강사는 VS Code의 Markdown 미리 보기로 열어 확인했다.

강사가 강조한 점은 두 가지다. 선임에게 며칠 동안 인수인계받던 일을 혼자 몇 분 만에 할 수 있다는 것, 그리고 질문에 "근거 파일을 알려 달라"를 붙이면 답이 맞는지 직접 확인하기 쉽다는 것이다.

---

### Mermaid란?

Mermaid는 글로 적은 정의를 다이어그램으로 바꿔 주는 문법이다. `A --> B`처럼 화살표 관계를 적으면 상자와 화살표 그림이 된다. Markdown 안에 코드 블록으로 넣을 수 있어서, 문서와 그림을 한 파일에 같이 둘 수 있다. 코드 흐름처럼 단계가 이어지는 내용을 보여 줄 때 쓴다.

---

## 음성으로 새 앱 만들기

빈 폴더 `excuse-generator`에서 새 세션을 열고 자동 모드로 바꾼 뒤 `/voice`로 음성 모드를 켰다. 이미 켜져 있었다면 같은 명령이 끄기로 동작하므로, 강사는 한 번 더 실행해 다시 켰다. 스페이스바를 누른 채 말하고 손을 떼면 말한 내용이 입력창에 들어가고, Enter로 보낸다.

요청한 것은 HTML 한 장짜리 "Developer Excuse Generator"다. 버튼을 누르면 "제 컴퓨터에서는 되는데요" 같은 개발자 변명이 무작위로 나온다. 변명 20개 이상, 애니메이션이 들어간 dark theme로 만들고 끝나면 브라우저에서 열어 달라고 했다. 1분이 안 돼 파일이 만들어지고 브라우저가 열렸다.

강사는 말이 타이핑보다 약 3배 빠르다고 했다. 그만큼 프롬프트를 자세히 쓰게 되고 결과도 좋아진다는 이유로, 긴 세션에서는 음성 모드를 권했다.

---

## 실패 테스트부터 쓰는 버그 수정

예제는 강의 자료로 주는 `expense-splitter`다. 금액을 여러 명에게 나누는 작은 Node.js 앱으로, 실행하려면 Node.js가 깔려 있어야 한다. `npm start -- 100 3`으로 100을 세 명에게 나누면 한 사람당 33.33이 되고 합계가 99.99라 1센트가 사라진다.

프롬프트는 네 단계를 순서대로 시켰다.

1. 이 현상을 재현하는 실패 테스트를 먼저 쓴다.
2. 나눈 금액의 합이 항상 총액과 같도록 고친다.
3. 테스트를 전부 실행해 확인한다.
4. 근본 원인을 두 줄로 설명한다.

23초 만에 수정이 끝났다. 다시 실행하니 남는 1센트가 한 사람에게 더해져 합계가 100이 됐다. GitHub 이슈의 버그를 가져와 고치고 PR까지 만드는 흐름은 S03 섹션 내용이다.

---

### 실패 테스트란?

버그가 남아 있는 동안에는 실패하도록 먼저 쓰는 테스트다. 고치기 전에 실패하는 것을 보고, 고친 뒤 통과하는 것을 보면 정말 그 버그가 고쳐졌다는 증거가 된다. AI에게 고치라고만 하면 "고쳤다"는 말만 남지만, 실패 테스트를 먼저 쓰게 하면 결과를 테스트로 확인할 수 있다.

---

## 코드 밖 업무 맡기기

예제는 강의 자료로 주는 `sales-data` 폴더의 매출 데이터다. 프롬프트는 두 가지를 요청했다.

- `sales.csv`를 정리해 `sales_clean.csv`로 저장하고, 고친 문제를 나열한다.
- 월요일 리더십 회의용 발표 자료를 만든다. 제목, 주요 수치, 월별 매출 차트, 상위 5개 제품, 발견한 데이터 문제, 권장 사항 3가지로 구성하고, 깔끔하게 만든 뒤 파일을 열어 달라고 했다.

4분 뒤 정리된 CSV와 PowerPoint 파일이 함께 나왔다. 강사는 손으로 하면 2~3시간 걸릴 일이라고 했다.

강사는 코딩 에이전트를 쓰는 사람과 같은 속도로 일하려면 이제 필수 기술이라고 정리했다. 그리고 매일 손으로 하던 일 하나를 Claude Code로 해 보고 얼마나 빨라졌는지 재 보라고 했다. 실패해도 괜찮고, 내 환경에서 Claude Code가 제대로 도는지 확인하는 의미도 있다고 했다.

## 따라 하기

세션 시작은 어느 시연이든 같다.

```bash
cd <프로젝트 폴더>
claude
```

- 세션 안에서 `Shift+Tab`을 반복해 자동 모드로 바꾼다.
- 음성 입력은 `/voice`로 켜고, 스페이스바를 누른 채 말한 뒤 떼고 Enter를 누른다.
- 버그 재현은 `expense-splitter` 폴더에서 `npm start -- 100 3`이다.

강사 프롬프트를 내 말로 줄인 뼈대다.

| 용도 | 프롬프트 |
|---|---|
| 온보딩 | 새 팀원이라 생각하고 이 앱이 하는 일, 기술 스택, 폴더 구조, 읽기 시작할 곳을 설명해 줘. 설명마다 근거 파일을 붙여 줘 |
| 흐름 추적 | 사용자가 X를 할 때 입력부터 화면 결과까지 코드 흐름을 따라가고, Mermaid 다이어그램과 함께 `onboarding.md`로 저장해 줘 |
| 버그 수정 | 재현하는 실패 테스트부터 쓰고, 고치고, 테스트를 전부 돌리고, 근본 원인을 두 줄로 설명해 줘 |

---

## 용어 정리

| 용어 | 뜻 |
|---|---|
| 자동 모드(auto mode) | 작업마다 승인을 묻지 않고 진행하는 권한 모드. `Shift+Tab`으로 바꾼다 |
| 음성 모드(voice mode) | `/voice`로 켜고 스페이스바를 누른 채 말해 프롬프트를 입력하는 기능 |
| 온보딩(onboarding) | 새로 합류한 사람이 프로젝트를 파악하는 과정 |
| Mermaid | 글로 적은 정의를 다이어그램으로 그려 주는 문법 |
| 실패 테스트(failing test) | 버그가 있는 동안 실패하도록 먼저 쓰는 테스트 |

---

## 확인할 것

- 강의의 "자동 모드"가 지금 버전의 auto mode인지, 파일 수정만 묻지 않는 accept edits 모드인지 대본만으로는 아직 확인 못 했다.
- `/voice`와 스페이스바를 누른 채 말하는 방식은 강의 시점 기준이다. 지금 버전에서 같은지 아직 확인 못 했다.
- 변명 생성 버튼의 원래 이름은 화면을 봐야 안다.
- `onboarding.md` 내용과 슬라이드 모양은 화면으로만 나와서 대본에 없다.
- 걸린 시간(40초, 2분 7초, 23초, 4분)은 강사 환경에서 잰 값이다.
- `expense-splitter`, `sales-data` 예제 폴더는 Udemy 강의 자료실에서 받아야 한다.
