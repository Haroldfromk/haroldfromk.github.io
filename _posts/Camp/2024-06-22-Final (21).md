## 심사 Reject 와 게스트 로그인

앱 심사를 넣었는데 Reject 이 되었다. 사유는 다음과 같다.

- 앱은 사용자가 계정 기반이 아닌 기능에 엑세스 하기 위해 등록하거나 로그인해야 합니다.
- 앱은 앱의 핵심 기능과 직접 관련이 있거나 법에 의해 요구되는 경우를 제외하고는 사용자가 기능하기 위해 개인 정보를 입력할 것을 요구하지 않을 수 있습니다.

처음에 우리는 무조건 로그인을 해야 앱을 사용할 수 있도록 했는데, 그것이 Reject 사유가 된 것이다. 추천, 지도처럼 계정이 없어도 볼 수 있는 기능까지 로그인을 요구했기 때문이다.

그래서 19일에 로그인 화면에 게스트 로그인 버튼을 먼저 추가했다. 버튼을 누르면 로그인 없이 바로 메인 TabBar 로 넘어간다.

## 커뮤니티 게스트 처리

Firebase 의 `User` 는 Firebase 가 로그인한 사람에게만 만들어 주는 타입이라 게스트용으로 직접 만들 수가 없다. 그래서 게스트를 표현할 타입을 따로 만들었다.

```swift
import FirebaseAuth

struct CustomUser {
    let uid: String
    let email: String?
    let isGuest: Bool

    init(guestUID: String) {
        self.uid = guestUID
        self.email = nil
        self.isGuest = true
    }
}
```

Firebase 의 `User` 와 비슷하게 쓰려고 uid, email 을 두고, 게스트인지 여부를 위해 isGuest 를 넣었다.

### SceneDelegate 에서 유저 구분

`switchToMainTabBarController` 는 첫 줄에서 `guard let user = Auth.auth().currentUser else { return }` 를 하고 있었다. 게스트는 여기서 막혀서 메인 화면으로 갈 수가 없었다. 이 guard 를 지우고, 유저가 없으면 `CustomUser` 를 만들도록 바꿨다.

### ChatVC 에서 게스트 제한

`ChatVC` 도 같은 방식으로 `user`, `customUser` 를 나누고 게스트용 init 을 추가했다. 그 다음 게스트일 때 달라져야 하는 곳을 하나씩 고쳤다.

먼저 입력창이다. 로그인 유저는 주황색에 "채팅을 입력해주세요!", 게스트는 회색에 "채팅 입력을 위해 로그인해주세요!" 를 보여준다. 이 설정은 `viewDidLoad` 에서 `viewWillAppear` 로 옮겨서 화면에 들어올 때마다 다시 반영되게 했다.

```swift
override func viewWillAppear(_ animated: Bool) {
    super.viewWillAppear(animated)
    setupMessageInputBar()
}

private func setupMessageInputBar() {
    if let user = user {
        messageInputBar.inputTextView.tintColor = ThemeColor.mainOrange
        messageInputBar.sendButton.setTitleColor(ThemeColor.mainOrange, for: .normal)
        messageInputBar.inputTextView.placeholder = "채팅을 입력해주세요!"
    } else if customUser != nil {
        messageInputBar.inputTextView.tintColor = .systemGray
        messageInputBar.sendButton.setTitleColor(.systemGray, for: .normal)
        messageInputBar.inputTextView.placeholder = "채팅 입력을 위해 로그인해주세요!"
    }
}
```

MessageKit 은 화면에 메시지를 그릴 때 "지금 보는 사람이 누구인지"(`currentSender`)를 알아야 내 메시지와 남의 메시지를 좌우로 나눈다. 게스트도 값을 돌려주도록 분기했다.

### 게스트 예외처리 보완

같은 날 오후에 몇 가지를 더 보완했다.

`user`, `customUser` 를 `let` 에서 `var` 로 바꾸고, `viewWillAppear` 에서 현재 로그인 상태를 다시 확인해서 넣어주도록 했다. init 때 받은 값만 믿지 않고, 화면에 들어올 때마다 지금 상태를 기준으로 하게 한 것이다.


## 추천페이지 생명주기 수정

추천 탭을 다시 누를 때마다 빈 화면에서 로딩이 시작되는 문제가 있었다. 원인은 데이터를 불러오는 시점이었다.

---

### ViewController 생명주기란?

ViewController 는 화면이 만들어지고, 보이고, 사라질 때마다 정해진 메서드가 불린다.

- `viewDidLoad`: 화면이 처음 메모리에 올라올 때 한 번만 불린다
- `viewWillAppear`: 화면이 보이기 직전에, 보일 때마다 불린다
- `viewDidDisappear`: 화면이 완전히 사라진 뒤에, 사라질 때마다 불린다

탭을 옮겨 다니면 `viewDidLoad` 는 다시 불리지 않지만, `viewWillAppear` 와 `viewDidDisappear` 는 매번 불린다.

---

### fetch 위치 옮기기

기존에는 `viewWillAppear` 에서 fetch 를 했다. 그래서 탭에 들어올 때마다 그제서야 데이터를 받기 시작했고, 받는 동안은 빈 화면이 보였다.

그래서 처음 한 번은 `viewDidLoad` 에서 fetch 하고, 그 다음부터는 화면이 사라질 때(`viewDidDisappear`) 미리 fetch 하도록 바꿨다. 추천페이지가 비활성화되어 있는 동안 미리 받아 두니까, 다시 들어왔을 때는 이미 데이터가 있다.

```swift
public override func viewDidLoad() {
    super.viewDidLoad()
    view.backgroundColor = .white
    setupCardSwiper()
    Task {
        await viewModel.fetchData()
    }
    bind()
}

public override func viewDidDisappear(_ animated: Bool) {
    super.viewDidDisappear(animated)
    cancellables.removeAll()
    Task {
        await viewModel.fetchData()
    }
    bind()
}

public override func viewWillAppear(_ animated: Bool) {
    navigationController?.navigationBar.isHidden = true
}
```

`viewDidDisappear` 에서 구독(`cancellables`)을 비운 뒤 `bind()` 를 다시 해서, 구독이 중복으로 쌓이지 않게 했다.
