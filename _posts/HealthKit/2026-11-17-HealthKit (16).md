#### CustomModifier 만들기

위에서 만든 available을 modifier로 바꿔서 코드를 좀 더 간략하게 바꿔본다.

새롭게 CustomModifier파일을 하나 만들어주고

```swift
import SwiftUI

struct ProminentButton: ViewModifier {

    var color: Color

    func body(content: Content) -> some View {
        if #available(iOS 26, *){
            content
                .buttonStyle(.glassProminent)
                .tint(color)
        } else {
            content
                .buttonStyle(.borderedProminent)
                .tint(color)
        }
    }
}

extension View {
    func prominentButton(color: Color) -> some View {
        modifier(ProminentButton(color: color))
    }
}
```

이렇게 Modifier 를 만들어준다.

이때 extension을 안쓰게 되면

```swift
.modifier(prominentButton(color: .pink))
```

이런식으로 써야해서 뭔가 modifier의 느낌이 잘 살지 않게된다.

```swift
// before           
if #available(iOS 26, *) {
    Button("Connect Apple Health") {
        isShowingHealthKitPermission = true

    .tint(.pink)

    Button("Connect Apple Health") {
        isShowingHealthKitPermission = true
    }
    .buttonStyle(.borderedProminent)
    .tint(.pink)
}        

// after
Button("Connect Apple Health") {
    isShowingHealthKitPermission = true
}
.prominentButton(color: .pink)          
```

이렇게 심플하게 된걸 알 수 있다.

다만 glassProminent 효과의 경우 확대해서 봐야 티가 날 정도라서 맥북에서 일반적인 시뮬레이터 크기로는 확인이 어렵다.

데이터 부분도 백그라운드를 줘보도록 한다.

코드는 위와 같고, 색상만 metric에 따라 바뀌도록 수정한다.

```swift
var backgroundColor: Color {
    metric == .steps ? .pink : .indigo
}

.background(LinearGradient(colors: [backgroundColor.opacity(0.25), .clear], startPoint: .topLeading, endPoint: .bottomTrailing))
```

하지만 실행해 보면 색이 바뀌지 않는데, 그건 List 때문이다.

List는 내부적으로 UIKit의 스크롤 뷰(iOS 16부터는 UICollectionView, 이전에는 UITableView)를 기반으로 그려지고, 이 스크롤 영역은 자체적으로 불투명한 기본 배경색을 가지고 있다.
`.background()`는 뷰의 뒤쪽에 레이어를 깔아주는 modifier라서, 그라데이션 자체는 정상적으로 적용되어 있지만 그 위를 List의 기본 배경이 덮고 있어 보이지 않는 것이다.

이때 iOS 16에서 추가된 `.scrollContentBackground(.hidden)`를 사용해준다.

```swift
List {
    ...
}
.scrollContentBackground(.hidden)
.background(LinearGradient(colors: [backgroundColor.opacity(0.25), .clear], startPoint: .topLeading, endPoint: .bottomTrailing))
```

List의 기본 배경이 숨겨지면서 뒤에 깔아둔 그라데이션이 보이게 된다.

![](https://pub-1fd8ca6711bd4f3f8b74d88a697b50f9.r2.dev/2026-11-17-HealthKit-16/iphone17pro-1123-110442.png)

다만 이건 List 전체의 배경만 숨기는 것이라 각 row의 배경(흰색 카드 부분)은 그대로 남는다.
row까지 투명하게 하고 싶다면 row에 `.listRowBackground(Color.clear)`를 따로 주면 된다.

강의에서는 

```swift
List(listData.reversed()) { data in
    LabeledContent {
        Text(data.value, format: .number.precision(.fractionLength(metric == .steps ? 0 : 1)))
    } label: {
        Text(data.date, format: .dateTime.month(.wide).day().year())
            .accessibilityLabel(data.date.accesibilityDate)
    }
    .listRowBackground(Color(.secondarySystemBackground).opacity(0.35))
    .accessibilityElement(children: .combine)
}
.navigationTitle(metric.title)
.scrollContentBackground(.hidden)
.background(LinearGradient(colors: [backgroundColor.opacity(0.25), .clear], startPoint: .topLeading, endPoint: .bottomTrailing))
```

secondaryBackground를 사용했다.

#### matchedTransitionSource

[matchedTransitionSource Docs](https://developer.apple.com/documentation/swiftui/customizabletoolbarcontent/matchedtransitionsource(id:in:)){:target="_blank"}

iOS 26의 기본 앱들(메일의 새 메일 작성 등)을 보면 툴바 버튼을 눌렀을 때 버튼에서 sheet가 쭉 늘어나듯 열리는 애니메이션이 있다.
이걸 zoom 전환이라고 하는데, 우리 앱의 Add Data 버튼에도 적용해 보려고 한다.

zoom 전환은 세 가지로 구성된다.

1. `@Namespace`로 이름 공간을 만든다.
2. 출발점(source)에 `matchedTransitionSource(id:in:)`를 붙인다.
3. 도착점(destination)에 `navigationTransition(.zoom(sourceID:in:))`을 붙인다.

여기서 `@Namespace`는 "어떤 뷰와 어떤 뷰가 짝인지"를 SwiftUI가 알 수 있게 해주는 일종의 그룹 이름이다.
출발점과 도착점에 같은 id(`"addData"`)와 같은 namespace(`zoomTransition`)를 넘겨주면 SwiftUI가 둘을 짝으로 인식하고, 그 사이를 이어주는 애니메이션을 만들어 준다.
id만 같고 namespace가 다르면 서로 다른 그룹으로 취급되어 연결되지 않는다.

```swift
@Namespace var zoomTransition

.overlay(content: {
    // 생략
})
.toolbar {
    if #available(iOS 26, *) {
        ToolbarItem {
            Button("Add Data", systemImage: "plus") {
                isShowingAddData = true
            }
            .buttonStyle(.glassProminent)
            .tint(metricColor)
        }
        .matchedTransitionSource(id: "addData", in: zoomTransition)
    } else {
        ToolbarItem {
            Button("Add Data", systemImage: "plus") {
                isShowingAddData = true
            }
        }
    }
}
```

`matchedTransitionSource`는 iOS 18부터 있었지만, 그때는 일반 View에만 붙일 수 있었다.
툴바 안의 버튼은 우리가 만든 View가 아니라 시스템이 툴바 아이템으로 다시 그려주기 때문에, Button에 붙여도 출발점으로 인식되지 않는다.
iOS 26부터 툴바 아이템(ToolbarItem)에 직접 붙일 수 있는 버전이 추가되었기 때문에, Button이 아니라 ToolbarItem으로 감싼 뒤 거기에 붙여줘야 한다.

그리고 sheet도

```swift
.sheet(isPresented: $isShowingAddData) {
    if #available(iOS 26, *) {
        addDataView
            .presentationDetents([.fraction(0.4)])
            .scrollContentBackground(.hidden)
            .navigationTransition(.zoom(sourceID: "addData", in: zoomTransition))
    } else {
        addDataView
            .presentationDetents([.fraction(0.4)])
    }
}
```

이렇게 버전에 따라 다르게 해준다.
`navigationTransition(.zoom)` 자체는 iOS 18부터 쓸 수 있지만, 출발점인 툴바 아이템 쪽이 iOS 26부터만 지정 가능하기 때문에 도착점도 iOS 26에서만 적용되도록 맞춰주었다.
